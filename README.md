# Agenti — автономное ИИ-агентство контента

Agenti — это веб-приложение, в котором команда ИИ-агентов автономно выполняет
заказы на контент (SMM-посты, экспертные статьи, email-рассылки) и зарабатывает
для агентства. Агенты работают на **GigaChat** (Сбер).

> Честная рамка: приложение генерирует контент и считает выручку по прайсу, но
> реальные деньги появляются, когда вы подключаете канал клиентов и оплату.
> Здесь готов рабочий «движок» агентства, на который это наращивается.

## Как это работает

Каждый заказ автоматически проходит конвейер агентов:

```
Бриф клиента
   │
   ▼
🧭 Стратег        — превращает бриф в план контента (аудитория, тезисы, CTA)
   │
   ▼
✍️  Копирайтер     — пишет черновик (свой агент под каждый формат:
   │                 пост / статья / рассылка)
   ▼
✦  Редактор        — вычитывает и доводит до финальной версии
   │
   ▼
Готовый контент + выручка по прайсу
```

Оркестратор (`app/agents/orchestrator.py`) последовательно вызывает агентов и
сохраняет результат каждого этапа.

## Стек

- **Backend:** FastAPI + SQLModel (SQLite, без внешней БД)
- **LLM:** GigaChat (синхронный клиент) с офлайн-стабом для демо/CI
- **Frontend:** статический дашборд (HTML/CSS/JS), раздаётся самим FastAPI
- **Тесты:** pytest · **Линт:** ruff · **Пакетный менеджер:** uv

## Запуск

```bash
cd backend
uv sync --extra dev

# (необязательно) реальный GigaChat — иначе работает демо-стаб:
cp .env.example .env
# впишите GIGACHAT_AUTH_KEY=...

uv run uvicorn app.main:app --reload
```

Откройте http://localhost:8000 — это дашборд (админка агентства).
Страница приёма заказов для клиентов: http://localhost:8000/order — клиент сам
оставляет бриф, после чего заказ появляется в админке.

Без ключа GigaChat приложение работает в **демо-режиме**: агенты возвращают
структурированную заглушку, так что весь поток (клиент → заказ → агенты →
выручка) можно посмотреть без сети.

## API

| Метод | Путь | Назначение |
|-------|------|-----------|
| GET | `/api/health` | статус и режим LLM (`gigachat` / `stub`) |
| GET | `/api/pricing` | прайс по типам контента (₽) |
| POST | `/api/clients` | добавить клиента |
| GET | `/api/clients` | список клиентов |
| POST | `/api/orders` | создать заказ (цена берётся из прайса) |
| POST | `/api/orders/intake` | публичная заявка: создаёт клиента и заказ разом |
| GET | `/api/orders` | список заказов |
| POST | `/api/orders/{id}/run` | запустить конвейер агентов |
| POST | `/api/orders/{id}/pay` | отметить счёт оплаченным |
| GET | `/api/orders/{id}/deliverable` | получить готовый контент |
| GET | `/api/revenue` | сводка по выручке (учитывает только оплаченные) |

## Прайс (по умолчанию)

| Услуга | Цена |
|--------|------|
| Пост для соцсетей | 1 500 ₽ |
| Email-рассылка | 3 500 ₽ |
| Экспертная статья | 6 000 ₽ |

Правится в `app/pricing.py`.

## Учёт оплат

Оплата ведётся вручную: у каждого заказа есть статус `unpaid` / `paid`. Кнопка
«Отметить оплаченным» (или `POST /api/orders/{id}/pay`) фиксирует оплату.
**Выручка считается только по оплаченным заказам**; невыполненные и выполненные,
но ещё не оплаченные заказы показываются как «Ожидает оплаты».

## Структура

```

  app/
    agents/        # Стратег, копирайтеры, редактор, оркестратор
    routers/       # clients, orders, revenue, health
    services/llm.py  # GigaChat + офлайн-стаб
    static/        # дашборд
    models.py      # Client / Order / Deliverable + схемы
    pricing.py     # прайс-лист
    db.py          # SQLite engine
    config.py      # настройки из env
    main.py        # точка входа FastAPI
  tests/
```
